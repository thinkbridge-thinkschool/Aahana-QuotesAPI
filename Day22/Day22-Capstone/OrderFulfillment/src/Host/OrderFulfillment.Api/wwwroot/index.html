How does this actually work?
  1. POST creates the Order and writes an OrderPlaced event to an outbox row, in the same database transaction — the API responds 201 immediately, before anything downstream has run.
  2. A background processor polls the outbox (every few seconds) and publishes that event onto the bus.
  3. Inventory reacts, reserves stock, and publishes either StockReserved or StockReservationFailed.
  4. Ordering reacts to that: Confirmed on success, or Cancelled (a compensating action, not an error) on failure.
  5. Payments reacts to Confirmed, captures a charge, and the order moves to PaymentReceived.
  6. Shipping reacts to that and dispatches — the order reaches Shipped, its final state.

Every hop is async and independently retryable — that's the whole point of the outbox pattern: nothing is lost even if the process restarts mid-saga.
